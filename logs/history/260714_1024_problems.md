# Problem Record (Troubleshooting)

**Severity**: High (incoherencia documental) — pero contenido técnico no afectado, solo referencias cruzadas.

## The Problem

El blueprint `ptservice_art_prop.md` (versión aprobada 2026-07-12) y los 15 artefactos CS derivados引用an códigos QMS (`P-PSEA-XX`, `F-PSEA-XX`, `I-PSEA-XX`, `DG-PSEA-XX`) que fueron renumerados por la matriz `docs/sgc/matriz_equivalencias_codigos_sgc_pea.md` aprobada el 2026-06-14, **un mes antes** de que el blueprint fuera terminado. La consecuencia operativa:

- Un lector que siga una referencia (e.g., "ver `F-PSEA-05A` para el anexo técnico de equipos") y abra el QMS buscando ese código, no encuentra el documento o encuentra uno diferente del esperado.
- Peor aún: el código `F-PSEA-13` colisiona. Bajo el código antiguo, `F-PSEA-13` era el "Paquete de homogeneidad y estabilidad" (H/E). Bajo la renumeración, `F-PSEA-13` ahora es el "Informe final de resultados" (que antes era `F-PSEA-04`). Si un artefacto dice "F-PSEA-13" sin contexto, el lector queda atrapado: ¿H/E o informe?
- En CS-11, la fila "F-PSEA-05A / F-PSEA-04 / calaire-app" mezclaba dos códigos antiguos que bajo la renumeración colapsan al mismo contenido vigente (`F-PSEA-04`) o a un código distinto (`F-PSEA-13` para informe, no para equipo).

## User-Requested Corrections

El usuario pidió "implementa las mejoras" después de la review (`logs/history/260714_0927_review-ptservice-art-impl.md`), que listaba este problema como #1 en la sección de "problema crítico" y proponía:

- Crear una tabla de equivalencias en `00_control/`.
- Aplicar la tabla a los artefactos que引用an los códigos con significado cambiado.
- Actualizar el blueprint (sección 19) en una próxima iteración.

## The Solution / Workaround

**Implementado en esta sesión:**

1. **`commercial_service/00_control/qms_code_equivalence.md`** — tabla canónica que lista cada código que引用an los artefactos, con su significado antiguo y el código vigente, más las implicaciones operativas (3 puntos críticos: informe final en `F-PSEA-13`, equipo en `F-PSEA-04`, quejas/apelaciones/confidencialidad en `P-PSEA-17/18/19` respectivamente).

2. **Header uniforme en los 15 artefactos CS** con la línea "QMS code reference" apuntando a la tabla, para que cualquier lector sepa dónde verificar antes de abrir el QMS.

3. **CS-11 corregido** — la fila ambigua del onboarding pack reescrita como `F-PSEA-04` (vigente, para equipo) + `F-PSEA-03` (vigente, para registro de participante), eliminando la colisión.

4. **Blueprint sección 19** — tabla de interfaces con QMS actualizada a códigos vigentes; nueva sub-sección 19.1 "Code renumbering note" que documenta el cambio, los puntos críticos para la capa comercial, y referencia a la tabla de equivalencias.

5. **CS-13 verificado** — usaba `F-PSEA-13` correctamente para el informe final; se añadió nota explícita de mapeo en el header.

## Learnings to Preserve

1. **Cualquier blueprint o spec que cite códigos institucionales debe tener una fecha de vigencia de esos códigos.** Si el QMS renumera, el blueprint debe ser actualizado al mismo tiempo o llevar una nota de "códigos al día YYYY-MM-DD, verificar contra matriz vigente antes de usar".

2. **Colisiones por reasignación de número** (caso `F-PSEA-13`: H/E antes, informe final ahora) son el riesgo más peligroso de una renumeración, peor que los cambios de significado puros. Una tabla de equivalencias debe marcar explícitamente estos casos.

3. **Documentos derivados (artefactos CS) deben llevar un puntero a la tabla de equivalencias, no memorizar los códigos.** De este modo, cuando el QMS vuelva a renumerar (cosa que pasa cada vez que se reordena el SGC), basta con actualizar la tabla y los headers; los artefactos no necesitan re-editarse.

4. **Las revisiones deben preceder a la implementación.** La review de implementación fue la que detectó el problema — sin ella, los artefactos hubieran quedado con referencias obsoletas y un nuevo usuario hubiera perdido tiempo descifrando el mismatch.

5. **Para futuras renumeraciones del QMS:** ejecutar `grep -r "P-PSEA\|F-PSEA\|I-PSEA\|DG-PSEA" commercial_service/` y revisar cada coincidencia contra la nueva matriz. El header "QMS code reference" en cada artefacto facilita este barrido.
